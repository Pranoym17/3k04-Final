# Integration decisions (Deliverable 3)

Taken by Claude Code on 25 November 2026 on the team's behalf. Each can be overruled; the reason is given so the
cost of overruling is clear.

| ID | Decision | Reason |
|---|---|---|
| D3-01 | The translation lives in one new file, `integration/adc_bridge.py`, run in the ADC process. Neither part imports it. | Both parts are already graded. A separate adapter keeps Part B at zero changes and Part A at one accessor. Part A's codec says "the Part B sub-team changes the message format: only this module changes"; rewriting `message_codec.py` to Part B's format would have broken Part A's own `badmsg`/`ack` demo commands and its tests' assumptions, so the adapter is the smaller diff. |
| D3-02 | Part B is the receiver and is not changed. Part A conforms through the adapter. | Part B already has a signed HTTPS interface with tests (M10, M15). Part A had no transport at all. |
| D3-03 | Part A gets one public read-only method, `AdcApplication.pending_wire()`. | The adapter needs the queued payloads. They were only reachable through the private `_queue`. The method uses Part A's own `MessageCodec.encode`, which had no caller before. |
| D3-04 | Part A's OutboundQueue is the only buffer. A message is acknowledged in Part A only after Part B answered "accepted" for it. | Keeps Part A's FR-COM-04 (ordered replay, nothing lost) true across the real link, and avoids a second queue that could disagree with the first. |
| D3-05 | A rejected message is never acknowledged; the queue holds. | A rejection with the wrong key would otherwise drop every message, including dispenses and alarms. Holding is visible on the ADC banner (stored count grows). Cost: one malformed message blocks the queue until fixed. |
| D3-06 | `configuration` is passed to Part A through `monitor_response` and acknowledged when Part A accepts it. The threshold value is kept by the adapter. | Part A has no reorder-threshold function. Part B computes Low itself from inventory and its confirmed threshold, so the ADC does not need to act on it. Stated in INTERFACE.md and the report as partly integrated. |
| D3-07 | `DISPENSE_RESULT` UNCERTAIN becomes a medium `alarm_notice`. DENIED and `AUTH_FAILED` are not sent. | UNCERTAIN means medication may have left the drawer without a stock change, which a pharmacist must count. Part B has no message type for denials, and adding one would change Part B. |
| D3-08 | `alarm_clear` is sent when the drawer behind an alarm is back IN_SERVICE (read from `drawer_report()`). | Part A emits no clear message. The drawer state is the public fact that the fault is cleared. |
| D3-09 | `message_id` = milliseconds since epoch second 1 700 000 000 at first sight, strictly increasing (`max(last + 1, now_ms)`). Replaced a boot-based formula at 15:35, see problem 8. | Part A restarts its counter at 1 on every boot, and Part B remembers accepted IDs for ever and silently discards repeats. Time-based increasing IDs cannot repeat across a restart unless the ADC averaged over 1000 messages a second or its clock was set back. Fits Part B's 10^12 limit until 2055. |
| D3-10 | The timestamp is taken when the adapter first sees a message. | So a message held through an outage keeps its real time and is recorded Late (Part B FR-COM-09). |
| D3-11 | The integrated ADC runs as `ADC-01` with `demo-key-ADC-01`. | That ID and key are already registered by Part B's demo seed, so no Part B change. Part A's cabinet ID is a constructor argument. |
| D3-12 | The adapter accepts the self-signed certificate (`--insecure`). | Part B always serves HTTPS with a self-signed lab certificate. Same choice as Part B's own simulator. |
| D3-13 | The integrated ADC console reuses Part A's `adc/main.py` loop unchanged by replacing `build()` and `input()` from `integration/run_adc.py`. It adds a real-time clock that still supports `advance`, a lock around every App call, and the 5 s hardware poll on a thread. | No change to Part A's console. Part A's main.py says swapping the simulated parts "is a change to these five lines and nothing else". The real poll is needed for Part A's 15 s link timeout to happen without typing `poll`. |
| D3-14 | Part A's D2 console commands `ack`, `linkup` and `linkdown` still work but simulate Part B; `ack MSG-n` would remove a message without sending it. DEMO.md says not to use them in the integrated demo. | Removing them would change Part A. |
| D3-15 | Part B's hard-coded `now + 60.0` uptime heartbeat (`system.py`, decision D23) is left as is. | It does not touch the ADC boundary. |
| D3-16 | Pushed to `Pranoym17/3k04-Final` only (the repo the user named). Nothing pushed to the Part A repo `Nijjea1/Software3K04-D2` or the Part B repo. | The user allowed pushing; the original part repos belong to their authors and stay as graded. |
| D3-17 | The Deliverable 1 and 2 PDFs and the handout were not copied into the repo. | Not needed to run anything; the repo visibility was not checked against course material. |
